\chapter{Introduction}
\label{ch:introduction}

This thesis studies how the configuration parameters of FINUFFT, a widely used
library for the nonuniform fast Fourier transform, affect the time a transform
takes. It also asks whether that effect can be modelled well enough to choose
better values than the library's defaults. This chapter explains why the
question matters, states the problem and the scope of the study, and sets out
its research questions and contributions.

\section{Background and Motivation}

In many scientific applications, including frequency analysis, data are sampled
at irregular locations rather than on a uniform grid. A magnetic resonance
scanner samples along spirals or radial spokes, and a radio interferometer
samples wherever its pairs of antennas happen to point. A molecular dynamics
code analyses particles that move continuously through space. Analysing such
data in the frequency domain calls for a Fourier transform between scattered
points and uniform frequencies. Evaluating that transform directly costs
$O(MN)$ operations for $M$ points and $N$ frequencies. The fast Fourier
transform would reduce the cost to $O(N \log N)$, but it applies only to
samples that are equally spaced. The nonuniform fast Fourier transform bridges
the two. It comes in three types: type~1 maps nonuniform points to uniform
frequencies, type~2 is its adjoint and maps uniform frequencies back to
nonuniform points, and type~3 maps nonuniform points to nonuniform
frequencies. For type~1, it spreads each scattered point onto a fine uniform grid using a
smooth kernel of finite width, transforms that grid with an ordinary FFT, and
then divides out the effect of the kernel. This recovers the speed of the FFT
at an accuracy the caller requests in advance.

The cost of that construction matters because it is rarely paid once. Iterative
image reconstruction in magnetic resonance imaging evaluates a transform and its
adjoint at every iteration. Gridding in radio interferometry repeats one for
every frequency channel and every time step, and particle-mesh methods in
molecular dynamics and cosmology evaluate one at every step of the simulation.
In each of these pipelines the transform is frequently the single most
expensive component, so the rate at which it runs sets the rate at which the
surrounding computation runs.

FINUFFT~\cite{barnett2019} is among the most widely used implementations.
Considerable effort has gone into making its inner loops fast. Its spreading
kernel, which distributes each point's value over the nearby cells of the fine
grid, is shaped so that it can be evaluated cheaply at run time, and its
evaluation is hand-vectorised. Spreading is also parallel: each thread
accumulates into a private subgrid, so that threads do not contend for the
shared output grid. Beyond these loops, its performance depends on a set of
configuration parameters whose values the library fixes by default. These are
the upsampling factor, the maximum subproblem size, the bin dimensions, whether
the points are sorted, and the thread count above which the adding stage
switches to atomic updates. This thesis concentrates on the first three, whose
best values depend on the transform. The upsampling factor sets how much larger
the fine grid used for spreading is than the output grid. The maximum
subproblem size sets how many points a thread spreads at a time, and the bin
dimensions set the size of the boxes the points are sorted into before
spreading.

Two properties make FINUFFT a suitable subject for studying how these parameters
affect performance. It is in production use, so its behaviour affects real
workloads rather than a benchmark written for the occasion. And it is built like
the other implementations of the algorithm, sorting the points into bins and
spreading them in independent subproblems. Insights gained from evaluating its
performance can therefore be used to tune other NUFFT libraries.

The algorithm proceeds in stages: it sorts the nonuniform
points, spreads them onto the fine grid, transforms that grid, and corrects for
the kernel. The configuration parameters decide how much work each stage is
given. A parameter that shrinks the work in one stage usually enlarges it in
another, so the fastest configuration is a balance rather than an extreme.
Unless the user overrides them, FINUFFT chooses these values itself, some by
simple heuristics and others from constants fixed when the library is built.
How well it chooses, and what is lost when it chooses badly, is the subject of
this thesis.

\section{Problem Statement}
\label{sec:problem_statement}

FINUFFT chooses the values of its configuration parameters automatically, but
mostly from fixed constants or simple rules rather than from the transform at
hand. The version of the library that preceded this thesis used the following
defaults and heuristics, all of which the user could override by any value in corresponding 
range:
\begin{itemize}
    \item the \emph{upsampling factor} $\sigma$, range is any real between 1.15 and 2.0, heuristics choose 
    $1.25$, or $2$ when the point density or the requested accuracy was high;
    \item the \emph{maximum subproblem size} $S_{\max}$, from $1$ to the number of
    points per thread $M/n_{\mathrm{thr}}$, was $10^5$ points in two
    and three dimensions and $10^4$ in one, or fewer if a thread had fewer points
    than that;
    \item the \emph{bin dimensions}, integer from $1$ to the fine-grid size $N_i$ along
    each axis, were $16$ grid cells along the $x$ axis and
    $4$ along the others, a constant compiled into the library;
    \item \emph{sorting of nonuniform points by coordinates}, either on or off,
    and was enabled by heuristics for inputs of
    realistic size;
    \item the \emph{atomic-update threshold}, any number of threads, was set to $10$.
\end{itemize}
These defaults were tuned by the authors for common combinations of transform
and CPU. They stay the same, however, while transforms vary widely in
dimension, point density, accuracy, thread count and the machine they run on.

The right value is hard to guess because each parameter affects performance
nonlinearly, through more than one stage of the transform. For example a type-1 transform runs in four stages. First, the points are \emph{sorted} into bins. Next, they
are \emph{spread} onto a fine grid: each thread gathers a subproblem of points,
spreads them into a private subgrid and adds that subgrid to the shared grid.
The grid is then transformed by an \emph{FFT}, and finally the result is
\emph{deconvolved} to remove the effect of the kernel.

Consider the upsampling factor, which fixes how much larger the fine grid is than
the output grid. Raising it enlarges that grid, so the FFT in the middle of the
algorithm transforms more data and takes longer. But a finer grid also places
the aliases the spreading kernel produces further apart. A narrower kernel then
suffices for the same accuracy, and spreading touches fewer cells for every
point it deposits. The same change therefore makes one stage more expensive and
another cheaper. Which effect wins depends on the number of points per grid
cell, the requested accuracy, and how much of the grid fits in cache. The
maximum subproblem size and the bin dimensions behave the same way. The
subproblem size trades gathering against adding, and the bin dimensions trade
the cost of the sort against that of spreading and adding. A user who wants to
set them well therefore needs to know more than that a parameter is important:
which stages it moves, in which directions, and what decides where the two
effects balance.

A faster configuration often exists. Beatty et al.~\cite{beatty2005}
showed that the conventional upsampling factor of two is not required. A whole
family of upsampling factors and kernel widths reaches any given accuracy, so
the grid can be made smaller if the kernel is made wider. How to choose within
that family has been approached by measurement. gNUFFTW~\cite{ou2017} tunes a
GPU nonuniform transform by running candidate configurations during planning and
keeping the fastest, and reports order-of-magnitude gains from the oversampling
ratio alone. FFTW~\cite{frigo2005} does the same for the ordinary FFT, assembling
each transform from interchangeable steps and timing the candidates on the
machine it finds itself on. General frameworks such as OpenTuner~\cite{ansel2014opentuner}
apply the idea to arbitrary programs. What all of these produce is a
configuration that is fast for a specific input, on the machine where the search
was run.

A search executes many transforms before it returns anything. It therefore
repays itself only when the same plan is executed many times, which is not how
a library call is typically used. Its answer carries no reason, so nothing about
it transfers: a value found at one point density, or on one cache hierarchy,
says nothing about another, and the search must be repeated. Moreover, a search
cannot say which part of the transform it improved, because it sees only the
total. That last limitation is not an accident of how searches are built. A
parameter that halves the cost of one stage and doubles the cost of another
leaves the total unchanged. An end-to-end timing then reports no effect where
two large effects have cancelled.

\section{Aim and Scope}
\label{sec:aim_scope}

The aim of this thesis is to explain how FINUFFT's configuration parameters
affect the cost of each stage of a type-1 transform, in which scattered points
are spread onto a uniform grid. A further aim is to use that explanation to
choose better parameter values than the defaults before the transform runs. To
this end, type-1 transforms of different dimensions, precisions and point
densities are benchmarked, and the duration of each stage is measured
separately. The dependencies between stage costs, transform parameters and CPU
characteristics such as cache sizes are then analysed, and models are developed
that predict performance from them. Finally, these models are evaluated before
a transform runs to select configuration parameters that provide better
performance than the library defaults.


\section{Research Questions}
\label{sec:research_questions}

This thesis addresses three questions.

\begin{enumerate}
    \item \textbf{Which of FINUFFT's configuration parameters affect performance
    significantly on the machine under test?}
    \item \textbf{Can models describe how changing each parameter affects the
    cost of the individual stages of the transform?} 
    \item \textbf{Can such models choose a better configuration before a
    transform runs?} 
\end{enumerate}

\section{Contributions}

The contributions of this thesis are of four kinds. They are a modified build
of FINUFFT, a set of measurements made with it, models that predict
measurement results, and a selection procedure built on those models.

\paragraph{Methodological}
\begin{itemize}
    \item \textbf{Bin dimensions exposed as public options.} The bin dimensions
    are compile-time constants in the released library. They are added as fields
    of the public options structure, \texttt{finufft\_opts}, so that they can be
    set at run time like any other parameter and their effect on performance
    studied.
\end{itemize}

\paragraph{Empirical}
\begin{itemize}
    \item \textbf{Explores better than default parameter configurations.} A
    search that varies all six parameters together finds configurations faster
    than the library defaults, the best of them by $23.3\%$ on the reference
    transform. The same search shows which parameters matter: whether the points
    are sorted dominates, and once sorting is enabled, the upsampling factor and
    the bin dimensions account for most of the remaining variation.

    \item \textbf{An explanation of the spreader parameters' trade-offs.} Each
    parameter makes one stage cheaper and another more expensive, and the
    balance shifts when the data a stage uses no longer fits in a cache level.
    Larger subproblems make adding cheaper but gathering more expensive; larger
    bins make sorting cheaper but spreading and adding more expensive.
\end{itemize}

\paragraph{Modelling}
\begin{itemize}
    \item \textbf{A closed-form model of subgrid size.} The average size of the
    subgrid produced by a given subproblem size and bin shape is derived in one,
    two and three dimensions and validated against
    subgrids logged by the spreader.

    \item \textbf{Cost models for the upsampling factor.} The cost of spreading
    as a function of the upsampling factor is reproduced across all three
    dimensions, so the effect of raising the upsampling factor on that stage can be evaluated without profiling.
    The cost of the FFT behaves differently depending on whether the fine grid
    fits in the last-level cache, at a grid size set by the cache rather than
    fitted to measurements.

    \item \textbf{A memory traffic model of the bin sort and the spreading
    stage.} The DRAM lines moved per point by each stage are expressed in terms
    of the bin dimensions, the maximum subproblem size, the kernel width, the
    density, the thread count and the cache sizes.
\end{itemize}

\paragraph{New proposed model}
\begin{itemize}
    \item \textbf{A selection procedure for the bin dimensions and the maximum
    subproblem size.} It evaluates the traffic model over combinations of maximum subproblem size and bin dimensions
    and picks one that generates least memory traffic.
\end{itemize}

\section{Thesis Organization}

The remainder of this thesis is organised as follows.
Chapter~\ref{ch:background} introduces the nonuniform fast Fourier transform,
the structure FINUFFT gives it, and the prior work on choosing parameters by
measurement.
Chapter~\ref{ch:methodology} describes the machine, the workloads and the
instrumentation on which every later measurement rests, including how the
stages of a subproblem are separated from one another.
Chapter~\ref{ch:parameter_importance} establishes where a transform spends its
time and which of the six parameters account for the variation in it, narrowing
the field for the two chapters that follow.
Chapter~\ref{ch:sigma_selection} takes the upsampling factor, the highest-ranked
of them, and analyses and models the two costs it trades against each other.
Chapter~\ref{ch:parameter_tuning} does the same for the parameters that govern
the spreader, the maximum subproblem size and the bin dimensions, and derives
the model of subgrid size on which their behaviour rests. It then combines
these results into a model of memory traffic, proposes a procedure that selects
both parameters from it, and evaluates that procedure on $54$ transforms.
Chapter~\ref{ch:conclusion} answers the research questions, states the
limitations of the study, and outlines future work.
